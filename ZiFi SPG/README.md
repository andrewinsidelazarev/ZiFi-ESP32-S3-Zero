# ZiFi SPG для ZiFi ESP32-S3 Zero

`zifi.spg` — интернет-клиент для ZX Evolution с TS-Conf. Программа открывает
каталоги vtrd.in, zxart.ee, prods.tslabs.info, bbb.retroscene.org, pouet.net и
других сайтов, скачивает игры, демо и образы дисков на SD-карту, показывает
тексты и картинки, играет AY-музыку.

Это переработка программы **ZiFi** Hacker VBI
([HackerVBI/ZiFi](https://github.com/HackerVBI/ZiFi), [zifi.vtrd.in](http://zifi.vtrd.in))
под адаптер ZiFi на ESP32-S3 с прошивкой из этого репозитория. Интерфейс, меню,
списки сайтов, просмотр текстов и картинок, проигрыватель музыки остались от
оригинала. Ниже перечислено, что изменено.

Готовая программа: [`build/zifi.spg`](build/zifi.spg).

## Главное

- **Исправлен файловый драйвер.** Старый FAT-движок Wild Commander
  (`WDFCVBI2.COD`) заменён исправленным ядром FAT32 из
  [Wild Commander Improved](https://github.com/andrewinsidelazarev/Wild-Commander-Improved),
  выделенным в самостоятельный драйвер
  [FAT32-Driver-ZX-Evolution](https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution).
- **Транзакционная перезапись файлов.** Файл с уже существующим именем сначала
  целиком пишется во временный и заменяет прежний только после успешной записи.
  Оборванная загрузка или ошибка записи не портят уже скачанный файл.
- **Нет текстового мусора в консоли.** Заодно пропало зависание мыши на
  реальной плате.
- **Нет артефактов на краю экрана.** Убраны тонкая линия по курсору на границе
  окна консоли и зелёная полоска в правом бордюре у нижней панели.
- **Индикатор скачивания работает и показывает реальный прогресс, а не
  имитацию.** Полоса заполняется пропорционально скачанному: 100 ячеек на весь
  файл.
- **Работа с ZiFi ESP32-S3**: двоичный протокол вместо AT-команд ESP8266,
  HTTPS, прокси для ретро-архивов, часы по NTP.

## Подробно

### Файловый драйвер

- Оригинал писал файлы FAT-движком Wild Commander (`WDFCVBI2.COD`, страница
  `#0F`). Теперь используется самостоятельный драйвер FAT32-Driver-ZX-Evolution
  (страницы `#0E` и `#0F`) — исправленное ядро FAT32 из Wild Commander
  Improved. Относительно ядра исходного Wild Commander в нём исправлено:
  - обе копии FAT обновляются согласованно, а на томе с одной активной FAT
    пишется именно она;
  - конец цепочки кластеров распознаётся верно, без перехода по
    несуществующим кластерам;
  - пустой файл создаётся без ошибочной цепочки кластеров;
  - длинное имя удаляется целиком, без записей-«призраков»;
  - короткие имена 8.3 получают правильные суффиксы `~1`…`~999`;
  - ошибка чтения или записи SD останавливает операцию, а не продолжает её с
    неверными данными;
  - дозапись (`APPEND`) заранее выделяет недостающую цепочку и публикует
    точный размер файла;
  - находится том внутри расширенного раздела (цепочка EBR): в исходном коде
    обход не доходил до логического тома;
  - недействительная подсказка FSInfo пропускается, свободное место ищется по
    FAT.
- Программа работает с драйвером через `fat32_adapter.asm`: чтение `zifi.ini`,
  создание каталогов, сохранение загрузок. Драйвер проверен 29 тестами,
  исполняющими его код Z80 на модельных образах SD. Подробности — в
  [FAT32.md](FAT32.md) и в README драйвера. `WDFCVBI2.COD` в сборку больше не
  входит.

### Транзакционная перезапись файлов

- Если файла с таким именем нет, он создаётся сразу.
- Если есть, новый файл целиком пишется во временный `ZIFITMP.$$`. Только после
  успешной записи и закрытия прежний файл удаляется, а временный получает его
  имя. Оборванная загрузка или ошибка записи оставляют прежний файл целым;
  остаток прерванной попытки удаляется при следующей замене в том же каталоге.
- FAT32 не ведёт журнала: если питание пропадёт ровно между удалением прежнего
  файла и переименованием, новый файл останется целым под именем `ZIFITMP.$$`.

### Мусор в консоли и зависание мыши

- Прокрутка консоли запускала DMA, у которого страница источника и приёмника
  одна и та же (`Text_page`). Такая пересылка ненадёжна: в консоли появлялись
  случайные символы. Теперь прокрутка идёт командами `LDIR`/`LDDR` с теми же
  адресами и объёмом. После этого пропало и зависание мыши на реальной плате,
  которое лечилось только выключением питания.
- Текстовая страница очищается до включения растровых прерываний, поэтому при
  старте не мелькает старое содержимое памяти.

### Артефакты на краю экрана

- Тонкая линия по курсору на границе окна консоли. `PALSEL` менялся посреди
  кадра, а VGA-удвоитель строк берёт режим от предыдущей строки и палитру от
  текущей: граничная строка выводилась с палитрой графики. Теперь `PALSEL` и
  `TSCONFIG` выставляются один раз при старте.
- Зелёная полоска в правом бордюре у нижней панели. Цвет бордюра FPGA меняет
  сразу, а режим — только со следующей строки, поэтому правый край последней
  строки консоли выводился цветом текстовой палитры (`CRAM[#F4]`, зелёный).
  Теперь бордюр постоянный (`GFX_BORDER`), и его цвет меняется вместе с режимом
  ровно на границе строк.
- После просмотра картинки восстанавливается `PALSEL`.

### Индикатор скачивания

- В оригинале индикатор был полосой активности: ячейка сдвигалась на каждые
  256 принятых байтов и шла по кругу, независимо от размера файла. Сколько
  скачано, по нему понять было нельзя.
- После перехода на протокол ESP32-S3 индикатор перестал двигаться совсем: шаг
  брался из старшего байта длины порции, а порция протокола не больше 255
  байтов, так что шаг всегда был нулевым.
- Теперь индикатор показывает реальный прогресс. Длину файла сообщает ESP
  (`Content-Length`), и полоса заполняется пропорционально принятому: 100
  ячеек на весь файл. Замер на загрузке 640 КиБ: ровно 100 шагов из 100 и в
  эмуляторе, и на настоящей плате (`tools/verify_progress_bar.py` в
  репозитории драйвера).
- Если сервер длину не назвал, реальный прогресс показать невозможно, и
  индикатор работает как полоса активности: ячейка на 256 байт.

### Связь с ESP

- Оригинал работал с модулем ESP8266 на стандартной AT-прошивке
  (`AT+CIPSTART`, `+IPD`, …); кроме того, была отдельная сборка для кабеля
  RS232. Теперь обмен идёт двоичным протоколом прошивки ZiFi ESP32-S3: пакет
  `[#5A][CMD][LEN_L][LEN_H][DATA…][CSUM]` через порты ZiFi
  (`shared/z80/zifi_uart.asm`, `shared/z80/proto.asm`, `net.asm`). Команды
  оригинала сохранены для сверки в [ORIGINAL_AT_COMMANDS.md](ORIGINAL_AT_COMMANDS.md).
- HTTP-запрос целиком выполняет ESP. Z80 получает код ответа HTTP,
  `Content-Length` и затем тело.
- Добавлен HTTPS: TLS, проверку сертификата и до пяти редиректов выполняет
  прошивка.
- `zifi.ini` при старте целиком уходит на ESP командой `WIFI_INI`. Прошивка
  подключается к Wi-Fi и возвращает адрес, выданный роутером; он выводится на
  экран.
- Удалены сборка для кабеля RS232 и самообновление с zifi.vtrd.in: там лежит
  оригинальная AT-версия, и её установка затёрла бы этот порт.

### Старт и диагностика

- При запуске программа проверяет, что прошивка ESP отвечает, выводит IP-адрес,
  сведения о прошивке и состояние прокси, затем делает пробный HTTP-запрос к
  zifi.vtrd.in. Причины сетевых ошибок (ESP не отвечает, сбой открытия или
  приёма, пустой ответ, тайм-аут) пишутся в консоль программы.

### Часы и каталог загрузок

- Оригинал брал дату с zifi.vtrd.in вместе с проверкой обновлений. Теперь время
  приходит по NTP через ESP; смещение часового пояса задаёт поле `time:` в
  `zifi.ini`, а `time:none` оставляет часы компьютера нетронутыми.
- Файлы по-прежнему сохраняются в `zifi/downloads/<дата>`, но каталог даты
  называется `ГГГГ-ММ-ДД` вместо `ДД_ММ_ГГГГ`: сортировка по имени совпадает с
  сортировкой по дате.

### Прокси для ретро-архивов

- Для vtrd.in, zxart.ee и pouet.net можно указать HTTP-прокси (`proxy_ip`,
  `proxy_port` в `zifi.ini`). При старте выводится, включён прокси, выключен
  или недоступен.

### Проверка скачанного

- Если сервер назвал `Content-Length`, файл принимается только при точном
  совпадении длины. Обрыв связи даёт ошибку, а не обрезанный файл.
- Файл `.zip` обязан начинаться с сигнатуры ZIP, поэтому страница ошибки
  PHP/HTML или ответ прокси не запишется на SD под видом архива.
- Превышение буфера загрузки 640 КиБ — явная ошибка.

## zifi.ini

Файл кладётся на SD-карту в `/zifi/zifi.ini`. В git он не хранится
(`.gitignore`), потому что содержит пароль Wi-Fi. Строки, начинающиеся с `;`, —
комментарии.

```ini
SSID: Your_WiFi_Network
password: Your_WiFi_Password
; Часовой пояс: смещение от UTC (от -14 до +14) или none — часы не трогать
time: +2
; Необязательный HTTP-прокси для vtrd.in, zxart.ee, pouet.net
proxy_ip: <адрес>
proxy_port: <порт>
```

## Сборка

Нужны `sjasmplus` и драйвер FAT32, клонированный рядом с этим репозиторием:

```
git clone https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution.git "FAT32 Driver"
```

`build.bat` собирает драйвер, затем `zifi.asm` (общие исходники берутся из
`shared/z80`) и упаковывает `build/zifi.spg` программой `_spg/spgbld.exe`.
Путь к `sjasmplus` задаёт переменная `SJASMPLUS`, путь к драйверу —
`FAT32_DRIVER_DIR`.
