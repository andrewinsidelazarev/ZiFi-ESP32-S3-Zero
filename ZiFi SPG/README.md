# ZiFi SPG для ZiFi ESP32-S3 Zero

`zifi.spg` — интернет-клиент для ZX Evolution с TS-Conf. Программа открывает
каталоги vtrd.in, zxart.ee, prods.tslabs.info, bbb.retroscene.org, pouet.net и
других сайтов, скачивает игры, демо и образы дисков на SD-карту, показывает
тексты и картинки, играет AY-музыку.

Это переработка программы **ZiFi** Hacker VBI
([HackerVBI/ZiFi](https://github.com/HackerVBI/ZiFi), [zifi.vtrd.in](http://zifi.vtrd.in))
под адаптер ZiFi на ESP32-S3 с прошивкой из этого репозитория. Интерфейс, меню,
списки сайтов, просмотр текстов и картинок, проигрыватель музыки остались от
оригинала. Ниже перечислено, что изменено.

Готовая программа: [`build/zifi.spg`](build/zifi.spg).

## Что изменено относительно оригинала VBI

### Связь с ESP

- Оригинал работал с модулем ESP8266 на стандартной AT-прошивке
  (`AT+CIPSTART`, `+IPD`, …); кроме того, была отдельная сборка для кабеля
  RS232. Теперь обмен идёт двоичным протоколом прошивки ZiFi ESP32-S3: пакет
  `[#5A][CMD][LEN_L][LEN_H][DATA…][CSUM]` через порты ZiFi
  (`shared/z80/zifi_uart.asm`, `shared/z80/proto.asm`, `net.asm`). Команды
  оригинала сохранены для сверки в [ORIGINAL_AT_COMMANDS.md](ORIGINAL_AT_COMMANDS.md).
- HTTP-запрос целиком выполняет ESP. Z80 получает код ответа HTTP,
  `Content-Length` и затем тело.
- Добавлен HTTPS: TLS, проверку сертификата и до пяти редиректов выполняет
  прошивка.
- `zifi.ini` при старте целиком уходит на ESP командой `WIFI_INI`. Прошивка
  подключается к Wi-Fi и возвращает адрес, выданный роутером; он выводится на
  экран.
- Удалены сборка для кабеля RS232 и самообновление с zifi.vtrd.in: там лежит
  оригинальная AT-версия, и её установка затёрла бы этот порт.

### Старт и диагностика

- При запуске программа проверяет, что прошивка ESP отвечает, выводит IP-адрес,
  сведения о прошивке и состояние прокси, затем делает пробный HTTP-запрос к
  zifi.vtrd.in. Причины сетевых ошибок (ESP не отвечает, сбой открытия или
  приёма, пустой ответ, тайм-аут) пишутся в консоль программы.

### Часы и каталог загрузок

- Оригинал брал дату с zifi.vtrd.in вместе с проверкой обновлений. Теперь время
  приходит по NTP через ESP; смещение часового пояса задаёт поле `time:` в
  `zifi.ini`, а `time:none` оставляет часы компьютера нетронутыми.
- Файлы по-прежнему сохраняются в `zifi/downloads/<дата>`, но каталог даты
  называется `ГГГГ-ММ-ДД` вместо `ДД_ММ_ГГГГ`: сортировка по имени совпадает с
  сортировкой по дате.

### Прокси для ретро-архивов

- Для vtrd.in, zxart.ee и pouet.net можно указать HTTP-прокси (`proxy_ip`,
  `proxy_port` в `zifi.ini`). При старте выводится, включён прокси, выключен
  или недоступен.

### Проверка скачанного

- Если сервер назвал `Content-Length`, файл принимается только при точном
  совпадении длины. Обрыв связи даёт ошибку, а не обрезанный файл.
- Файл `.zip` обязан начинаться с сигнатуры ZIP, поэтому страница ошибки
  PHP/HTML или ответ прокси не запишется на SD под видом архива.
- Превышение буфера загрузки 640 КиБ — явная ошибка.

### Запись на SD: самостоятельный FAT32

- Оригинал писал файлы FAT-движком Wild Commander (`WDFCVBI2.COD`, страница
  `#0F`). Теперь используется самостоятельный драйвер
  [FAT32-Driver-ZX-Evolution](https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution)
  (страницы `#0E` и `#0F`), подключённый через `fat32_adapter.asm`: чтение
  `zifi.ini`, создание каталогов, запись с точным размером файла. Подробности —
  в [FAT32.md](FAT32.md). `WDFCVBI2.COD` в сборку больше не входит.
- Если файл с таким именем уже есть, новый пишется во временный `ZIFITMP.$$` и
  заменяет прежний только после успешной записи. При сбое прежний файл
  остаётся цел.

### Индикатор загрузки

- Оригинал сдвигал ячейку на каждые 256 принятых байтов. Если сервер сообщил
  длину файла, индикатор теперь показывает долю скачанного: 100 ячеек на весь
  файл. Без длины работает прежний режим.

### Экран и мышь

- Прокрутка консоли больше не запускает DMA с одной и той же страницей источника
  и приёмника, вместо него `LDIR`/`LDDR`. Ушли случайный мусор в консоли и
  зависание мыши на реальной плате.
- Текстовая страница очищается до включения растровых прерываний, поэтому при
  старте не мелькает старое содержимое памяти.
- `TSCONFIG` и `PALSEL` выставляются один раз при старте, а не посреди кадра:
  на VGA пропала тонкая линия по курсору на границе окна консоли.
- Бордюр постоянный (`GFX_BORDER`): FPGA сама меняет его цвет вместе с режимом
  в начале строки, поэтому пропала зелёная полоска справа на границе нижней
  панели. После просмотра картинки восстанавливается `PALSEL`.

## zifi.ini

Файл кладётся на SD-карту в `/zifi/zifi.ini`. В git он не хранится
(`.gitignore`), потому что содержит пароль Wi-Fi. Строки, начинающиеся с `;`, —
комментарии.

```ini
SSID: Your_WiFi_Network
password: Your_WiFi_Password
; Часовой пояс: смещение от UTC (от -14 до +14) или none — часы не трогать
time: +2
; Необязательный HTTP-прокси для vtrd.in, zxart.ee, pouet.net
proxy_ip: <адрес>
proxy_port: <порт>
```

## Сборка

Нужны `sjasmplus` и драйвер FAT32, клонированный рядом с этим репозиторием:

```
git clone https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution.git "FAT32 Driver"
```

`build.bat` собирает драйвер, затем `zifi.asm` (общие исходники берутся из
`shared/z80`) и упаковывает `build/zifi.spg` программой `_spg/spgbld.exe`.
Путь к `sjasmplus` задаёт переменная `SJASMPLUS`, путь к драйверу —
`FAT32_DRIVER_DIR`.
