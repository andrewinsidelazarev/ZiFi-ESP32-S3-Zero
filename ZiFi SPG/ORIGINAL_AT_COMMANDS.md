# AT-команды оригинального ZiFi

Источник для сверки: текущий исходник оригинальной версии
`C:\Users\Администратор\Desktop\WC\ZiFi\zifi.asm`.

Ниже перечислены команды именно из исполняемого Wi-Fi-варианта. Команды,
которые только объявлены в таблице строк или упомянуты в комментариях, вынесены
в отдельный раздел.

Все команды завершаются `CR LF`.

## Инициализация ESP8266

| Команда | Когда отправляется | Назначение |
|---|---|---|
| `ATE0` | При запуске | Отключить эхо введённых AT-команд. |
| `AT+GMR` | При запуске | Получить версию AT-прошивки и SDK; найденная строка `AT version:` показывается на экране. |
| `AT+CWMODE_DEF=1` | При запуске | Установить режим станции и сохранить его как режим по умолчанию. |
| `AT+CWAUTOCONN=0` | При запуске | Отключить автоматическое подключение ESP к сохранённой точке доступа. |
| `AT+CIPMUX=0` | При запуске | Выбрать одно TCP-соединение без номера link ID. |
| `AT+CIPRECVMODE=1` | При запуске, пробно | Включить пассивный приём TCP. Если команда возвращает `OK`, оригинал использует `CIPRECVDATA`; иначе остаётся старый активный приём через `+IPD`. |
| `AT+CIPDINFO=0` | Только после успешного `AT+CIPRECVMODE=1` | Не добавлять IP и порт удалённого узла в уведомления `+IPD`. |
| `AT+CWJAP_CUR="<SSID>","<password>"` | После чтения `zifi.ini` | Подключиться к точке доступа без сохранения пары SSID/пароль во flash ESP. |

Статические строки находятся у меток `cmd_at`, `cmd_gmr`,
`cmd_ciprecvmode`, `cmd_cipdinfo`, `cmd_cwmode`, `cmd_cwautoconn`,
`cmd_cipmux` и `cmd_cwjap`. Порядок вызовов задаёт `init_zifi`.

## Получение данных по HTTP

| Команда | Когда отправляется | Назначение |
|---|---|---|
| `AT+CIPSTART="TCP","<host>",80` | Перед каждым HTTP-запросом | Открыть TCP-соединение с сервером. Имя узла подставляет `parse_url`. |
| `AT+CIPSEND=<length>` | После подключения | Запросить передачу готового HTTP-запроса длиной `length`; после приглашения `>` отправляются сырые байты запроса. |
| `AT+CIPRECVDATA=1024` | Для каждой порции в пассивном режиме | Забрать до 1024 накопленных TCP-байтов. Реальная длина берётся из заголовка ответа `+CIPRECVDATA,...`. |
| `AT+CIPCLOSE` | При восстановлении после ошибки открытия соединения | Закрыть текущее одиночное TCP-соединение перед повторной попыткой. При штатной загрузке конец определяется по удалённому закрытию `CLOSED`. |

Строки находятся у меток `cmd_conn2site`, `cmd_cipsend`,
`cmd_ciprecvdata` и `cmd_cipclose`; основной цикл загрузки начинается с
`zifi_get`.

## Обрабатываемые ответы и события

Это не команды Z80 → ESP, но от них зависит работа оригинального парсера:

- `OK`, `ERROR`, `FAIL`, `ALREADY CONNECT`, `SEND OK`;
- приглашение `>` после `AT+CIPSEND`;
- `+IPD,<length>:` в активном режиме;
- уведомление `+IPD,<total_length>` и ответ
  `+CIPRECVDATA,<actual_length>:<data>` в пассивном режиме;
- `CLOSED` при закрытии TCP-соединения.

## Объявлены, но текущим Wi-Fi-кодом не отправляются

| Команда | Состояние в исходнике |
|---|---|
| `AT+UART_CUR=115200,8,1,0,3` | Строка существует, вызов в `init_zifi` закомментирован. |
| `AT+CWQAP` | Строка и закомментированный вызов существуют; штатно не отправляется. |
| `AT+CWLAP` | Строка существует, вызовов нет. |
| `AT+CIPSTA?` | Строка существует, вызов закомментирован. |
| `AT+CIPMODE...` | Есть только поясняющий комментарий рядом с `CIPSTART`; готовой команды и вызова нет. |
