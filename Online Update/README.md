# ZiFi Online Update

`ZIFIUPD.WMF` — пользовательский плагин Wild Commander для автономного
обновления ZiFi ESP32-S3 Zero. Компьютер, Python, IP-адрес и `update.sna` для
обычного обновления не нужны.

## Установка

1. На ESP должна быть прошивка `s3-native-0.6.69` или новее. Для первого
   перехода с более старой версии один раз используйте `firmware/update.sna` и
   штатный `tools/esp_tool.py`.
2. Скопируйте `build/ZIFIUPD.WMF` в `/WC`.
3. Проверьте файл `/zifi/zifi.ini`: обязательны действующие `ssid:` и
   `password:`.
4. Запустите `ZiFi Online Update` из меню плагинов Wild Commander.
5. Дождитесь полей `Current` и `Available`. Статус отдельно сообщает, является
   ли опубликованная версия новой, старой или той же самой.
6. Нажмите `Enter` для установки либо переустановки. `Esc` до подтверждения
   отменяет операцию.

Предварительная проверка читает только HTTPS-манифест и не открывает Flash на
запись. Плагин намеренно разрешает установку того же опубликованного образа
поверх той же версии: при статусе `Same version` Enter остаётся активным.

## Что проверяется

ESP использует существующий проверяемый HTTPS-тракт с Mozilla CA bundle.
`firmware/firmware.sha256` содержит строку `VERSION` и SHA-256 обоих образов.
При открытии плагина ESP читает этот манифест и возвращает опубликованную версию.
После Enter манифест читается повторно, выбирается строка именно `firmware.bin`,
затем потоково получается `firmware/firmware.bin`.

До записи проверяется application-заголовок ESP32-S3. Данные идут только в
неактивный OTA-раздел и одновременно хэшируются. При несовпадении SHA-256,
обрыве, неверной длине или ошибке Flash вызывается `Update.abort()`, поэтому
текущий загрузочный слот остаётся прежним. После полного совпадения SHA-256 ESP
отправляет плагину успешный ответ, переключает OTA-слот и перезапускается.

`firmware.factory.bin` не загружается и не принимается этим обновлятором.

## Сборка

```powershell
cd "Online Update"
.\build.bat
```

Результат: `build/ZIFIUPD.WMF`.
