# Прошивка ESP32-S3-Zero

После запуска `..\build.bat` здесь создаются два разных образа:

- `firmware.factory.bin` — bootloader, таблица разделов и приложение; пишется
  при первой установке по адресу `0x0`;
- `firmware.bin` — только приложение с адресом раздела `0x10000`; не следует
  записывать этот файл по адресу `0x0`.

Образ `s3-native-0.6.67` поддерживает Native `zifi.spg`, NTP, FTP, SMB2/SMB3 и безопасное
обновление по Wi-Fi. В этой версии SMB ограничен проверенным диалектом 3.0.2,
требует подпись сообщений, поддерживает формат перечисления каталогов Windows
`FileFullDirectoryInformation`, раздельно учитывает одновременные деревья
`IPC$` и `SD`, перечисляет ресурс `SD` через минимальный `srvsvc`, выдаёт
каталоги потоково по одной записи и публикуется для Проводника через WS-Discovery.
Ответы `CREATE` возвращают запрошенные Windows контексты `MxAc` и `QFid`, а
идентификатор объекта совпадает в `QUERY_DIRECTORY`, `QFid` и
`FileInternalInformation`.
Связанные `CREATE + QUERY_DIRECTORY` возвращаются одной compound-цепочкой.
Холодный `QUERY_DIRECTORY` не строит синхронно полный снимок до EOF, поэтому
первая выдача каталога не удерживает весь compound-ответ на время полного
обхода SD.
Асинхронный `STATUS_PENDING` получает только READ, входящий в единственный
физический FILEX-сервис. Следующие READ хранятся маленькими дескрипторами и до
продвижения удерживают credits клиента. После каждого финального ответа окно
сдвигается на один запрос, поэтому серверная очередь имеет постоянную глубину
и не растёт вместе с размером файла.
Прямой HTTPS проверяет сертификаты по встроенному Mozilla CA-bundle. Стек
сетевой задачи увеличен до 16 КиБ для TLS-рукопожатия, а крупный буфер запроса
вынесен из стека. Поле `NETSTK` в `SYS_INFO` показывает минимальный оставшийся
запас стека после фактически выполненных операций.

В обычном образе диагностический журнал полностью выключен при компиляции.
Отдельный профиль `esp32s3_zero_log` создаёт `s3-native-0.6.67-log`: он хранит
не более 256 записей в кольцевом flash-файле размером 48 КиБ. Скачать этот
журнал после запуска update.sna можно командой
`py -u tools\esp_tool.py --net IP --log zifi.log`. Обычная версия ответит
`ERR log disabled` и не создаёт журнал.

Версия 0.6.7 освобождает оборванный SMB-сеанс до приёма следующего,
автоматически перезапускает TCP/445 после ошибки и повторяет WSD Hello
каждые 30 секунд. Для нового 16-КиБ окна FTP нужен `ZIFIFTP.WMF` v0.12 из
соседнего каталога `..\FTP Server\build`; старый плагин продолжит работать
через совместимый протокол по 512 байт, но без нового ускорения. FTP-порт
появляется только после запуска плагина и успешной команды `FTP_START`; сама
загрузка ESP и подключение Wi-Fi listener не открывают.

## Первая установка через USB-C

1. Извлеките переходник из основной платы. Одновременное питание от USB-C и
   контакта 3,3 В переходником не развязано.
2. Удерживая `BOOT`, подключите USB-C. После появления устройства отпустите
   кнопку.
3. Установите официальный `esptool` и запишите factory-образ:

```powershell
py -m pip install --upgrade esptool
py -m esptool --chip esp32s3 --port COM5 write-flash 0x0 firmware.factory.bin
```

Замените `COM5` фактическим портом. После успешной проверки записи отключите
USB-C и только затем устанавливайте переходник обратно.

## Последующие обновления по воздуху

После первой USB-установки один раз запустите совместимую Native-программу,
которая посылает `WIFI_INI` с вашим `zifi.ini` (`zifi.spg` либо
`NTPTIME.WMF`). Прошивка сохранит конфигурацию и дальше сама подключится после
любого reset.

1. Запустите `update.sna` на ZX и оставьте экран `Updater: <IP>:8267` активным.
2. Не нажимайте клавиши во время передачи.
3. Из корня проекта выполните:

```powershell
py -u tools\esp_tool.py --net 192.168.1.108 --bin firmware\firmware.bin
```

Вместо примера `192.168.1.108` используйте IP с экрана; допустим также
`--net auto`. После 100% утилита обязана получить от ESP строку `OK` с тем же
SHA-256. Только после этого ESP переключает OTA-слот и перезагружается.

Для OTA разрешён только `firmware.bin`. `firmware.factory.bin` содержит
bootloader и таблицу разделов; PC-утилита и ESP отвергают его по заголовку.
Если новая версия не запустит UART, VFS и сетевую задачу, bootloader вернётся к
предыдущему подтверждённому слоту.
