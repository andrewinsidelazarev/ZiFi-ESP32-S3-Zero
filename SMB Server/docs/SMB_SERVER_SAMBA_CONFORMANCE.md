# Соответствие ZiFi SMB фактическому обмену Windows ↔ Samba

Эталонный захват и полная таблица операций находятся в
[`SMB_PROTOCOL_WINDOWS_VS_SAMBA.md`](SMB_PROTOCOL_WINDOWS_VS_SAMBA.md).
Ниже зафиксировано состояние ZiFi SMB после сопоставления с этой трассой.

## Итог по операциям

| Строки эталона | Операция | Состояние ZiFi SMB | Проверка или ограничение |
|---|---|---|---|
| `O00` | `NEGOTIATE`, `SESSION_SETUP`, `TREE_CONNECT`, служебный `IOCTL` | реализовано | отдельные SessionId/TreeId, стабильный ServerGuid, окно 16 credits |
| `O01`, `O14` | открытие и перечисление каталога | реализовано | related compound `CREATE + QUERY_DIRECTORY + QUERY_DIRECTORY`, точные `NextCommand`, flags и padding проверяются TEST 19 |
| `O02` | создание каталога | реализовано | физический `MKDIR`, инвалидация родителя и событие `DIR_NAME/ADDED` |
| `O03` | создание пустого файла | реализовано | файл материализуется до успешного `CREATE`; событие `FILE_NAME/ADDED` |
| `O04`, `O07`, `O08` | запись, flush, append и random write | реализовано | позиционная запись, фиксированный PSRAM-пул, ответ после физической записи |
| `O05`, `O12`, `O13` | размер, времена и FAT-атрибуты | реализовано | метаданные возвращаются согласованно из кэша и сохраняются FILEX |
| `O06` | чтение и повторное чтение из нового сеанса | реализовано | 32-битный offset, async `PENDING → SUCCESS`, проверка данных в TEST 1–14 и 20 |
| `O09` | byte-range lock/unlock | реализовано | конфликты между разными SMB Open и освобождение на `CLOSE`, TEST 23 |
| `O10`, `O11` | truncate и extend | реализовано | `SET_EOF32`, отложенный reserve и нулевое физическое расширение на `FLUSH/CLOSE` |
| `O15`, `O26` | rename файла и каталога | реализовано | перемещение/замена FILEX; notify возвращает одну пару `OLD_NAME + NEW_NAME` |
| `O16`, `O17` | копирование и копирование с заменой | реализовано | tail-first Windows CopyFile, EOF reserve, sharing violation вместо повреждения активного reader |
| `O18` | alternate data stream | отклоняется | как в эталонной Samba без `streams_xattr`: FAT не имеет named streams |
| `O19` | hard link | `STATUS_NOT_SUPPORTED` | FAT/FILEX не предоставляет операцию ссылки; копировать данные вместо hard link нельзя |
| `O20`, `O21` | query/set security descriptor | `STATUS_NOT_SUPPORTED` | FAT/FILEX не хранит ACL. Фиктивный защищённый DACL ранее ломал Windows CopyFile; успешная, но непостоянная ACL была бы ложной семантикой |
| `O22` | `CHANGE_NOTIFY` и `CANCEL` | реализовано | отдельный async `STATUS_PENDING`, финальный `FILE_NOTIFY_INFORMATION`, тот же MessageId/AsyncId, финальный credit 0; точная отмена даёт `STATUS_CANCELLED`, TEST 25 |
| `O23`, `O27`–`O31` | delete-on-close, удаление файлов/каталогов | реализовано | непустой каталог даёт `STATUS_DIRECTORY_NOT_EMPTY`; успешное удаление порождает `REMOVED` |
| `O24`, `O25` | отсутствующий объект и непустой каталог | реализовано | точные отрицательные NTSTATUS без изменения носителя |
| `O32` | отключение | реализовано | `TREE_DISCONNECT` закрывает только своё дерево; `LOGOFF` не разрушает соседний сеанс, TEST 21 и 26 |

## Исправленный async-контракт `CHANGE_NOTIFY`

ZiFi теперь повторяет наблюдавшуюся у Samba последовательность:

1. запрос закрепляется за открытым каталогом, его поколением, MessageId и
   фильтром;
2. сервер немедленно возвращает отдельный async `STATUS_PENDING` и выдаёт
   уникальный AsyncId;
3. подтверждённое создание, запись, изменение EOF/атрибутов, rename или
   удаление завершает только подходящую подписку;
4. обычное событие возвращается как `FILE_NOTIFY_INFORMATION`; rename одного
   каталога кодируется двумя записями `RENAMED_OLD_NAME` и
   `RENAMED_NEW_NAME` с корректным `NextEntryOffset`;
5. `CANCEL` ищет исходный запрос по AsyncId и завершает его
   `STATUS_CANCELLED`; отдельного ответа на сам `CANCEL` нет;
6. `CLOSE`, `TREE_DISCONNECT` и разрыв соединения освобождают подписку вместе
   с её SMB Open.

События формируются для изменений, выполненных через этот экземпляр SMB.
FILEX не имеет фонового журнала FAT, поэтому правка карты другим ZX-плагином
в обход сервера не может породить live-notify; после следующего перечисления
каталога клиент всё равно получит фактическое содержимое.

## Сознательные отличия от Linux Samba

- Эталон согласовал SMB 3.1.1; текущая libsmb2-сборка ZiFi объявляет максимум
  SMB 3.0.2. Это не меняет файловые структуры из захваченного workload, но
  является реальным отличием диалекта.
- ZiFi отвечает `oplock_level = NONE` и не выдаёт lease из `RqLs`. Выдать
  кэширование без менеджера lease-break небезопасно: Windows могла бы держать
  устаревшие данные. `DH2Q` также не обещается как durable handle.
- ACL и hard links не эмулируются поверх FAT, потому что их невозможно
  сохранить с требуемой семантикой.
- Подписание SMB включено. Оно защищает целостность пакетов, но не шифрует
  payload; трафик остаётся пригодным для протокольного захвата.

## Граница проверки

Хостовая сборка MSVC и все 30 регрессионных сценариев прошли, включая
`CHANGE_NOTIFY` с `ADDED`, парой rename и `CANCELLED`, общий FIFO физических
операций, независимые курсоры каталогов и 600001-байтный WRITE/FLUSH с чтением
в новом сеансе без повреждённых байтов. Релизная прошивка
`s3-native-0.6.74` собрана, установлена на ESP32-S3 Zero и подтверждена реальным
копированием файла через Проводник на SD-карту ZX Evolution. Это аппаратное
подтверждение файлового копирования; отдельный побайтовый хэш результата в
этом пользовательском прогоне не снимался.
