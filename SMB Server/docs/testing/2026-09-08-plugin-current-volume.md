# ZIFISMB.WMF v0.5.9: текущий том и возврат в WC

Дата проверки: 8 сентября 2026 года.

## Изменение поведения

Плагин публикует корень тома активной панели Wild Commander. Клонирование
контекста панели сохраняет выбранный раздел устройства. Поиск
`/zifi/zifi.ini` на запасной SD1 или SD2 не меняет расшариваемый том.

Имя ресурса и поля `Share`, `volume`, `UNC` используют номер устройства из WC:
например, `0:\` становится `\\ZX-Evo\0`. При выходе плагин останавливает SMB,
закрывает окно, восстанавливает панельный IX и возвращает штатный код `3`.
[WC v1.10i от 8 сентября 2026 года](https://github.com/andrewinsidelazarev/Wild-Commander-Improved/releases/tag/v1.10i-2026-09-08)
по этому коду перечитывает обе панели с сохранением активной. В прежнем WC
перечитывается только активная панель.

## Сборка и машинный код

`SMB Server/build.bat`, SjASMPlus 1.18.3: 0 ошибок, 0 предупреждений.
Повторная сборка из дерева публикации побайтно совпала с проверенным WMF:

| Артефакт | Размер | SHA-256 |
| --- | ---: | --- |
| `SMB Server/build/ZIFISMB.WMF` | 16 896 байт | `9442684F0E65718445C1698F2AAD80C3DAE233854CFE89EE64609D5030104125` |

Исполняемый образ занимает ровно окно `#8000…#BFFF`: `mainEnd = #C000`.
Таблицы CRC находятся на `#BE00` и `#BF00`; проверка границы в ассемблере проходит.

## Проверки

- Все 6 тестов `SMB Server/tests/test_context_z80.py` прошли на машинном коде
  новой сборки. Проверены устройства 0…6, сохранение выбранного раздела,
  INI на исходном томе и на другой SD, ошибки поиска, восстановление корня,
  порядок закрытия окна, исходный IX и код возврата `3`.
- Аудит CRC того же WMF проверил 256 записей таблицы и 67 426 входных
  векторов, включая все одно- и двухбайтовые значения, пустой буфер, разные
  выравнивания и полное окно 16 352 байта с концом на `#10000`.
  Результаты совпали с `binascii.crc_hqx(data, 0xFFFF)`.
- Дополнительная проверка в другом интерпретаторе Z80 охватила 6 граничных
  случаев. Подтверждены точные диапазоны чтения и отсутствие записи вне
  служебного счётчика и стека.
- После изменения общего `shared/z80/config.asm` пересобраны FTP, NTP и
  Online Update. Все три WMF побайтно совпали с опубликованными файлами:
  новый режим `CONFIG_ACTIVE_VOLUME` включён только для SMB.

Запуск тестов из корня репозитория после сборки (Python и пакет `z80`):

```powershell
python "SMB Server/tests/test_context_z80.py"
```

Версия остаётся `s3-native-0.6.91`. Образы взяты из опубликованного коммита
`0f11dc490ad60d5821d9efd090566ffb9bd49766` и в обновлении плагина не меняются:

| Артефакт | Размер | SHA-256 |
| --- | ---: | --- |
| `firmware/firmware.bin` | 1 169 648 байт | `F32F565F7273388646E6CD15047048958B13352EC5FBD6D00781C0ED11D3F074` |
| `firmware/firmware.factory.bin` | 1 235 184 байта | `B7A56F83FDCEBA98C52A4DB69EA968F7AEBA1542C08C07620FFD68F96299F295` |

`platformio.ini` и `firmware/firmware.sha256` также сохранены без изменений.

## Границы проверки

Тесты плагина исполняют настоящий машинный код с моделью API WC, но не
эмулируют физический диск. В рамках подготовки публикации устройство не
перепрошивалось; полный набор регрессий ESP повторно не запускался.

Сообщённое зависание копирования ПК → Evo при потере фокуса приложения
остаётся открытой проблемой. Эта публикация не заявляет его исправление.
